Програма оновлення програмного забезпечення керування дроном 


1. Мета
Програма повинна віддалено оновлювати програмне забезпечення керування дроном (UI) на пристрої керування (стімдек) з визначеного віддаленого сервера.

2. Основні терміни
2.1. ПЗ пристрою керування скорочено називається надалі програма керування дроном (UI) на пристрої керування.
2.2. Оновлення програмного забезпечення це процес зміни програмного забезпечення шляхом заміни, додавання або вилучення відповідних файлів (виконавчих, конфігураційним, баз даних), які використовує програмне забезпечення пристрою керування.
2.3. Файли оновлення це файли, які використовує програмне забезпечення, та які підлягають заміні при поточному оновлені.
2.4. Файл архіву вважаємо файл, якій архівує та стискає файли оновлення, якій завантажуються з серверу та розархівовуються перед оновленням на пристрої керування.
2.5. Програмою оновлення надалі називаємо програмне забезпечення на пристрої керування, яка виконує поточне оновлення програми керування дроном (UI).
2.6. Актуальна версія ПЗ пристрою керування є така поточна версія програми керування дроном на пристрої керування, файли оновлення якої такі самі як в поточному файлі архіву на сервері.
2.7. Попередня версія ПЗ пристрою керування є така версія програми керування дроном на пристрої керування, яка відповідає перед поточним оновлення.
2.9. Сервером називається віддалений комп'ютер, якій зберігає актуальний файл архіву та надає його для виконання оновлення на відповідному пристрою керування.
2.10. Клієнт це пристрій керування, який отримує актуальний файл архіву з віддаленого сервера для проведення оновлення.

3.1 Функції програми оновлення на сервері:
- Встановлення необхідності оновлення на пристроях керування з встановленого набору пристроїв керування.
- Встановлення зв'язку з пристроєм керування в разі необхідності проведення на ньому оновлення.
- Копіювання актуального файлу архіву на пристрій керування для проведення оновлення.
- Віддалене розпакування актуального архівного файлу на пристрої керування після копіювання файлу архіву.
3.2 Функції програми оновлення на пристрої керування
- Перевірка необхідності оновлення при отриманні актуальної версії.
- Заміна файлів оновлення програмного забезпечення на пристрої керування.
- Збереження файлів оновлення попередньої версії ПЗ пристрою керування, з метою забезпечення можливості повернення попередньої версії.
- Можливість повернення попередньої версії програмного забезпечення.
- Логування процесу оновлення як на пристрої керування так і на сервері.


4. Вимоги до програми оновлення 

4.1. Програма оновлення повинна виконувати вказані функції.
4.2. Ініціатором оновлення являється програма на сервері. При необхідності оновлення програмного забезпечення, актуальний архівний файл неявно та без дозволу користувача копіюється з сервера на пристрій керування при наявності з'єднання.
4.2. Програма оновлення виконує функції як неявно так і за командою користувача пристроєм керування.
4.3. Програма оновлення неявно перевіряє необхідність проведення оновлення при увімкненні пристрою керування; при цьому діалогове вікно не з'являється. 
4.4. Взаємодія програми оновлення з користувачам виконуються за допомогою діалогового вікна.
4.5. Заміна актуальних файлів оновлення виконується тільки за згодою користувача пристроєм керування, шляхом натискання відповідної кнопки діалогового вікна.
4.6. Користувач повинен мати можливість відтермінування оновлення.
4.7. Користувач повинен мати можливість відміни оновлення.
4.8. Користувач повинен мати можливість повернути попередню версію ПЗ за допомогою функцій діалогового вікна.
4.9. Перед оновленням програма керування дроном зупиняються, щоб була можливість замінити файли оновлення. Після оновлення, пристрій керування перезавантажується. 


5. Криттерії
- Критерієм актуальності версії є однакові хеш-значення файлів архіву на серері та на пристрої керування.
- Файли оновлення розпаковуються з архівного файлу в папку UpDate відразу після отримання копії актуального архівного файлу з серверу. Після заміни файлів оновлення у відповідних папках ПО, папка UpDate видаляється. Таким чином, критерієм, що файли оновлення були замінені у відповідних папках ПО, є відсутність папки UpDate; якщо папки UpDate існує, то оновлення не відбулось та готове до заміни файлів оновлення. Цей критерій використовується при відміні оновлення або відкладені оновлення.


6. Опис роботи програма оновлення

6.1. Робота сервера з файлами оновлення
6.1.1. На сервері в файлі /home/pi/theWD/ClientList.txt зберігається список клієнтів, що підлягають оновленню програмного забезпечення. Кожна стрічка містить інформацію про підключення до клієнта зі сторони сервера та стан його оновлення. Наприклад
10.168.103.42 update.7z 9aae…40c6 deck /home/deck/Downloads/UpDt/ /home/pi/.ssh/keyTo10.168.103.42
де перший аргумент IP-адреса пристрою керування, другий - назва файлу архіву (update.7z), третій - SHA-хеш значення файлу архіву останнього вдалого оновлення,  четвертий - ім'я Linux-користувача клієнта (deck), п'ятий - шлях до папки зі сторони клієнта куда копіюється та розархівовується файл архіву, шостий - повний шлях до ssh-ключа з'єднання на сервері.
6.1.2. В тій самій папці на сервері зберігається актуальний архівний файл  /home/pi/theWD/update.7z запакований в форматі 7z, що містить файли оновлення програмного забезпечення та файл зі списком директорій на стороні клієнті, кути будуть замінюватись відповідні файлі. Якщо відбувається оновлення, то цей архівний файл замінюється актуальним архівним файлом.
6.1.3. В тій самій папці на сервері знаходиться скрипт-файл /home/pi/theWD/UpdateClientList.sh, який проводить опитування списку клієнтів ClientList.txt. Якщо хеш-значення архівного файлу клієнта зі спису ClientList.txt відрізняється від  хеш-значення актуального архівного файлу update.7z, то перевіряється ssh-з'єднання з відповідним клієнтом. При наявності з'єднання актуальний файл архіву копіюється клієнту (пристрою керування) в відповідну папку та в тій папці розпаковується в папку UpDate. При вдалому копіюванні та розархівуванні, стрічка цього клієнта в файлі ClientList.txt змінюється новим хеш-значення актуального архівного файлу як ознака того, що актуальний архівний файл вже скопійований та розархівований на стороні клієнта (пристрою керування) та не зєднуватись з цим клієнтом при наступному опитуванні.
6.1.4. Копіювання та розпакування документуються а файлі /home/pi/theWD/Log.txt, де зазначається дата та час копіювання, хеш-значення копійованого файлу, папка на пристрої керування куди було скопійовано, серійний номер пристрою керування.
 
6.2. Програма оновлення клієнта
Програма оновлення запускається автоматично при ввімкненні пристрою керування або при натискання ярлику на Desktop.
6.2.1 Для постійного моніторингу актуальності версії, програма оновлення запускається автоматично при увімкненні пристрою керування, при цьому виконуються наступні процедури:
1) Неявно перевіряється наявність розпакованої папки UpDate з актуальними файлами оновлення.
2) Якщо папки UpDate не існує, що означає що не має актуального оновлення, то програма оновлення завершує роботу. 
Якщо папки UpDate існує, то з'являється діалогове вікно вибору: оновлення зараз (кнопка ВСТАНОВИТИ НОВУ ВЕРСІЮ); або оновлення при наступнову увімкненні пристрою керування (кнопка ЗАКРИТИ); або оновлення при увімкненні пристрою керування (кнопка ВІДТЕРМІНУВАТИ ОНОВЛЕННЯ), при якому сплине встановлений час відтермінування (3 дні по замовчуванню).
3) Якщо вибране оновлення зараз (кнопка “ВСТАНОВИТИ НОВУ ВЕРСІЮ”), то:
- програма оновлення видаляє папку з попередньою версією програмного забезпечення (BackUp), створює нову папку для збереження поточної (перед цим оновленням) версії ПЗ та записує в цю папку відповідні поточні файли, набір яких відповідає списку директорій вказаних у файлі UpdatePathList актуальної версії;
- копіює поточний файлі списку директорій UpdatePathList в папку BackUp;
- перезаписує файли оновлення з папки UpDate у папки програмного забезпечення клієнта відповідно списку директорій в файлі UpdatePathList.
- видаляє папку UpDate як ознаку завершення поточного оновлення.
4) Якщо натиснута кнопка “ЗАКРИТИ”, то програма оновлення зупиняється. Програма оновлення знов запуститься при наступному увімкнені пристрою керування разом з перевіркою актуальності версії. Оскільки з попереднього виконання програми папка UpDate з вмістом файлів оновлення не була видалена, то з'являється теж саме діалогове вікно з пропозицією оновлення, відміною (ЗАКРИТИ) або відтермінування.
5) Якщо натиснута кнопка відтермінування (“ВІДТЕРМІНУВАТИ ОНОВЛЕННЯ”), то програма записує поточний час в визначений файл та завершує програму. При наступному увімкнені пристрою керування, програма перевіряє чи не сплинув встановлений час з моменту вказаному в файлі. Якщо час не слину, то програма відразу зупиняється до наступного увімкнення пристрою керування. Якщо час сплинув та існує папка UpDate (ознака незавершаного оновлення), то запускається діалогове вікно запускається з описаними вище кнопками. 

6.2.2. Для виконання функцій не пов'язаних з автоматичним оновленням, таких як повернення попередньої версії, повторне оновлення з існуючого архіву, використовується інтерфейс користувача у вигляді діалогового вікна, який запускається по натисканню ярлику “SoftUpdate” на пристрою керування (на desktop). Діалогове вікно відрізняється від попереднього діалогу при автоматичному оновленні. Це діалогове вікно надалі називається користувацьким діалогом та має три кнопки.
1) Кнопка “Повернути попередню версію” виконує повернення попередньої версії шляхом копіювання файлів оновлення з папки BackUp у відповідні папки ПО. Процедура виконує наступні дії:
- перевіряє існування папки BackUp;
- зупиняє програма керування дроном щоб уможливити копіювання файлів оновлення;
- копіює файлів оновлення з папки BackUp у відповідні папки ПО.
Після виконання цієї процедури файл архіву залишається не зміним з останнього копіювання з серверу та доступний для повторного оновлення за допомогою кнопки  “ОНОВИТИ З АРХІВУ”. 
3) Кнопка “ОНОВИТИ З АРХІВУ” оновлює програму існуючим в цей момент файлом архиву та виконує наступні процедури:
- перевіряє чи існує файл архіву;
- розархівування файлу архіву, який є в цей момент у клієнта, в папку UpDate;
- зупиняє програма керування дроном щоб уможливити копіювання файлів оновлення;
- копіює файлів оновлення з папки UpDate у відповідні папки ПО;
- видаляє папку UpDate по закінченню копіювання.
При виконанні цієї процедури не відбувається збереження попередньої версії ПО.
4) Кнопка “ЗАКРИТИ” закриває діалогове вікно та завершує виконання програми оновлення.


7. Структура програми оновлення

Програма оновлення SoftUpdate являє собою виконавчий файл діалогового застосунку, написаний на основі фреймворку QT5 мовою програмування C++ для операційної системи Linux. В залежності від аргументу команди запуску застосунку програма оновлення запускається або в варіанті для автоматичного запуску або в користувацькому варіанті, призначений для запуску по ярлику. 
При автозапуску після увімкнення пристрою керування команда запуску SoftUpdate не має аргументу. Автоматичний запуск при увімкненні пристрою керування забезпечується налаштуванням Desktop Linux OS (або SteamOS). 
При запуску по ярлику, команта запуску програми має аргумент –update, який додається в властивості ярлику.
При запуску застосунку або при натисканні кнопки діалогу запускається відповідна процедура, яка виконується Bash-скриптом ToUpdateFromServer.sh. Цей Bash-скриптом знаходиться в тій самій папці що виконавчий файл програми оновлення SoftUpdate. Bash-скрипт оновлення ToUpdateFromServer.sh виконує процедури в залежності від аргументу команд запуску Bash-скрипта. 
- Опис процедур, які запускаються з відповідними аргументами команди, можна переглянути командою: ToUpdateFromServer.sh -h;
- При увімкненні пристрою керування програма оновлення запускає скрипт з аргументом –ping;
- При натисканні кнопки “ВСТАНОВИТИ НОВУ ВЕРСІЮ” діалогу після увімкнені пристрою керування запускається скрипт аргументом --replace;
- При натисканні кнопки “Повернути попередню версію” користувацького діалогу запускається скрипт аргументом --restore;
- При натисканні кнопки “ОНОВИТИ З АРХІВУ” користувацького діалогу запускається скрипт аргументом --extract.
- При натисненні кнопки “ВІДТЕРМІНУВАТИ ОНОВЛЕННЯ” зберігається поточний timestamp в файлі PostponedUpdateTime. При наявності цього файлу програма оновлення автоматично не запускається на протязі визначеного часу (3 дні). Як сплине цей час, то програма оновлення зможе атоматично запускатись, а файл PostponedUpdateTime видаляється. Час очікування в секундах з моменту натискання цієї кнопки задається змінною AUTORUN_POSTPONE_TIME_SEC в скриті ToUpdateFromServer.sh. Початково цей час дорівнює 259200 сек, що відповідає трьом дням.


8. Розгортання програми оновлення на пристрої керування

8.1. Автоматичне розгортання програми оновлення

8.1.1. Для зручного встановлення програми оновлення з автоматичною зміною конфігурації сервера та пристрою керування пропонується скрипт розгортання deployFromServer.sh, який копіюється у відповідну папу пристрою керування (клієнта), з якої буде запускатись програма оновлення, зберігатись архівний файл та папка з попередньою версією. Для проведення автоматичного розгортання обов'язкове з'єднання з сервером. При наявному з'єднання з сервером програма розгортання виконує наступні дії:
- програма оновлення копіюється з сервера на пристрій керування;
- розгортається в зазначену папку;
- створює автоматичний запуск програми оновлення при увімкнені пристрою керування;
- створює ярлик користувацького діалогу:
- конфігурується та встановлюється VPN- з'єднання сервера з клієнтом;
- генерирует ssh-ключи та встановлює ssh-з'єднання з сервера до пристрою керування.
8.1.2. Програма розгортання deployFromServer.sh повинна знаходитись с папці, в якій буде встановлена програма оновлення. Наприклад:
cd /home/deck/Downloads/
Програма розгортання вимагає аргументи для правильного та автоматичного встановлення:
sudo ./deployFromServer.sh VPNadress deck SteamPW "-P 2222 pi@77.222.152.213" ServerPW
де
VPNadress - дозволена VPN адреса;
deck - Linux користувацьке ім'я пристрою керування;
SteamPW - пароль пристрою керування;
"-P 2222 pi@77.222.152.213" - адреса сервера в формі scp команди, якщо заданий порт сервера то аргумент повинне бути з великої -P;
ServerPW - пароль сервера.
Наприклад:
sudo ./deployFromServer.sh 10.168.103.70 deck Pasword1 "-P 2222 pi@77.222.152.213" Pasword2

8.2. Розгортання програми вручну вимагає наступні дії:
- Підключити пристрій керування до Інтернету.
- Встановити з'єднання пристрою керування з сервером ( по ssh).
- Скопіювати файли програми оновлення з сервера на пристрій керування у відповідну папку та надати їм відповідні права.
- Встановити необхідні програми: net-tools, sshpass, wireguard, resolvconf. Якщо resolvconf щойно встанвлений, то пристрій керування необхідно перезавантажити.  
- Згенерувати ключи для wireguard конфігурації з метою встановлення VPN з'єднання.
- Створити wireguard конфігураційний файл /etc/wireguard/wg0.conf на пристрої керування та запустити wireguard.
- Додати peer цього VPN з'єднання в wireguard конфігураційний файл серверас /etc/wireguard/wg0.conf та перезавантажити wireguard на сервері.
- Згенерувани ssh-ключи на сервері та встановити ssh-зєднання сервера зі стімдеком (ssh-keygen).
- Додати стрічку на Сервері в файл списку клієнтів /home/pi/theWD/ClientList.txt
- Створити ярлика на desktop пристрої керування:
Права кнопка миші на desktop / Create new / Link to Application… / 
/ Application / Name: SoftUpdate 
/ Application / Program: шлях до програми оновлення
/ Application / Argument: –update
/ Application / Work path: шлях до папки програми оновлення
- Автозапуск при увімкненні на пристрої керування:
/System Settings / Autostart / + Add New (вверху зліва) / +Application… 
/ Browse / шлях до програми оновлення.


9. Вимоги

9.1. Вимоги до робочої директорії на севері
- Робоча директорія на сервері призначена для зберігання файлу архіву, до якого надається доступ для віддаленого копіювання файлу архіву на пристрої керування.
- Робоча директорія повинна мати права запису та читання для всіх користувачів. Власник (owner) повинен мати доступ для виконання, щоб мати можливість запакувати архів.
- Робоча папка повинна мати резерв пам'яті на диску сервера для зберігання файлу архіву та  файлу звіту про оновлення користувачів. 
- файл /home/pi/deploy, який приймає участь в розгортанні програми оновлення зі сторони сервера, повинен мати root та sudo права доступу без паролю. 

9.2. Вимоги до архівного файлу
- Архівний файл оновлення є запакована програмою 7z папка під назвою UpDate, яка містить файли програми керування дроном, що підлягають оновленню, та файл зі списком відповідних діректорій, куди відповідні файли оновлення повинні копіюватись при оновленні.
- Назва архівного файлу повинна бути update.7z .
- Файл зі списком директорій вставляється в bash-скрип, тож не повинен мати додатковий тексту. Наведений приклад повного тексту файлу зі списком:
filePathList["autopilot_control"]="/usr/bin/"
filePathList["gamepad_udp_run"]="/usr/bin/"
filePathList["GUI_1_0"]="/usr/bin/"
де назва файлу вказується між квадратними скобками з кавичками після filePathList, відповідний шлях вказується в кавичках після знаку рівності тієї самої стрічки. Обмежень по кількості файлів в списку немає.
- Файл зі списком директорій повинен мати назву UpdatePathList та повинен мати Linux формат.
- Розмір архівного файлу, та дві розархівовані папки цього архіву (для UpDate та BackUp) не повинен перевищувати допустимий об’єм пам'яті на пристрої керування.
